Overview, Problem Statement, Objectives

📝 1. Project Overview
Project Title:

Copier Portal: AI-Powered Copier Analytics & Privacy Masking Dashboard

Description (ภาษาไทย):

ระบบแดชบอร์ดอัจฉริยะที่ใช้ AI Normalization ในการแปลงข้อมูลรายงานเครื่องพิมพ์ต่างรูปแบบให้อยู่ในฐานข้อมูลเดียวกัน ทำการเข้ารหัสข้อมูลส่วนบุคคล (PDPA Masking) อัตโนมัติก่อนส่งออก และประมวลผลข้อมูลเปรียบเทียบสถิติการเติบโตแบบปีต่อปี (Year-over-Year) เพื่อการควบคุมต้นทุน

Business Context:

ใช้งานในหน่วยงานสนับสนุนไอทีและฝ่ายการเงินขององค์กรที่ต้องการรวมรวมสถิติการใช้วัสดุสิ้นเปลืองการพิมพ์จากเครื่องพิมพ์หลากหลายยี่ห้อ (เช่น RICOH, Fuji Xerox)

🚨 2. Problem Statement
Current Problem:

โครงสร้างรายงานการพิมพ์ (CSV/Excel) ของผู้ผลิตเครื่องพิมพ์แต่ละยี่ห้อมีคอลัมน์และหัวตารางที่สะกดต่างกัน ทำให้ต้องเขียนโค้ดเฉพาะเจาะจงหรือทำงานแบบแมนนวล และมีข้อมูลส่วนบุคคล เช่น User ID และชื่อพนักงานปะปนอยู่ซึ่งเสี่ยงต่อการผิดกฎหมาย PDPA หากไม่มีระบบกรองที่ดี

Impact of Problem:

เกิดความผิดพลาดในการรวมสถิติ เสียเวลาวิเคราะห์ และเสี่ยงต่อการรั่วไหลของข้อมูลระบุตัวตนพนักงานเมื่อส่งออกรายงานสรุปสถิติให้ฝ่ายการเงิน

Proposed Solution:

ใช้ AI ในการจับคู่โครงสร้างคอลัมน์ (Schema Mapping) แบบไดนามิก ผนวกกับระบบ Masking ข้อมูลตามบทบาทผู้ใช้ (Role-based access) เพื่อล้างข้อมูลพนักงานโดยยังสามารถจับคู่ประวัติและเปรียบเทียบค่าใช้จ่ายรายปี (YoY) ได้อย่างถูกต้อง

รูปที่ 1: หน้าจอรายงานสรุปยอดการใช้งานเครื่องพิมพ์พร้อมกราฟวิเคราะห์แนวโน้ม (Desktop View)
🎯 3. Objectives — SMART Goals
  • ลดเวลาการประมวลผลข้อมูล จากการรวมรายงานต่างยี่ห้อแมนนวล 4 ชั่วโมงต่อเดือน เหลือไม่เกิน 2 นาทีด้วยระบบนำเข้าอัตโนมัติ (100% Automated)
  • การันตีความปลอดภัย PDPA 100% ข้อมูลระบุตัวตน (User ID และชื่อ) จะต้องถูกเข้ารหัส / Masking ก่อนการแปลงไฟล์หรือการส่งออกรายงานในกลุ่มผู้ใช้ปกติ
  • วิเคราะห์ความคุ้มทุนข้ามปี (YoY Growth Analysis) ระบบต้องคำนวณและชี้วัดสัดส่วนการเติบโตหรือยอดลดลงของค่าบริการได้เป็นเปอร์เซ็นต์แบบปีต่อปีเทียบเดือนตรงกัน
  • ลดโอกาสการเกิดข้อผิดพลาด (SLA Accuracy) ข้อมูลจำนวนหน้าและราคาค่าบริการรวมต้องคำนวณถูกต้องตามตารางเรตบริการปัจจุบันด้วยความถูกต้อง 100%

🔍 4. Scope (ขอบเขตโปรเจกต์)
In Scope:
  • การนำเข้าไฟล์ CSV/Excel ของเครื่องพิมพ์ยี่ห้อต่างๆ
  • ระบบ AI Mapping หัวตารางเพื่อเก็บข้อมูลลง DB โครงสร้างกลาง
  • กลไก Masking ข้อมูลผู้ใช้แยกบทบาท (Admin / User ทั่วไป)
  • การแสดงผลกราฟแนวโน้ม และกราฟเปรียบเทียบสถิติรายปี (YoY)
  • ระบบบันทึก Log กิจกรรมการนำเข้าและนำออกไฟล์
Out of Scope:
  • การดึงยอดพิมพ์แบบ SNMP Real-time
  • ระบบชำระเงินค่าบริการออนไลน์ (Payment Gateway)

🤖 5. AI / LLM / RAG Components
LLM Model Used: Gemini 1.5 Flash / GPT-4o-mini สำหรับการทำ Dynamic Header Extraction & Schema Mapping เพื่อแมปคอลัมน์ที่ไม่ตรงกันให้อยู่ในมาตรฐานเดียวกัน
RAG / Knowledge Base: ตารางอัตราเรตค่าบริการล่าสุด (Rates) และประวัติการพิมพ์ย้อนหลัง เพื่อใช้ในการวิเคราะห์ความผิดปกติ (Anomaly Detection)
Agent / Workflow: AI Agent สำหรับการวิเคราะห์หาปริมาณการพิมพ์และราคาบริการที่สูงผิดปกติข้ามรอบงวดรายงาน (Usage & Cost Anomaly Alert Agent)
AI Processing Workflow:
• Input: ไฟล์รายงานการใช้งานเครื่องพิมพ์แบบดิบ (CSV/Excel) และอัตราเรตค่าบริการ
• AI Processing: LLM วิเคราะห์หัวตารางเพื่อทำโครงสร้าง Schema Normalization และกรองความผิดปกติของข้อมูลการพิมพ์
• Output: ข้อมูลประวัติการประมวลผลการใช้อุปกรณ์ที่กรอง/Masking แล้วพร้อมเข้าสู่ DB และคำแนะนำกรณีพฤติกรรมใช้งานผิดปกติ
• Human Review: ผู้ดูแลระบบ (Admin) ตรวจทานการแจ้งเตือนความผิดปกติ และกดอนุมัติเขียนทับข้อมูล (Force Import) กรณีรอบรายงานซ้ำ
Hallucination / Risk Mitigation: กำหนด Strict JSON schema ใน Prompt บังคับให้ LLM คืนค่าแมปปิ้งโครงสร้าง 100% พร้อมสร้างระบบควบคุมขีดจำกัดความถูกต้อง (Rule-based boundaries check) ในฝั่งหลังบ้าน
⚙️ 6. Workflow / Architecture (ขั้นตอนการทำงาน)
1

Upload File (Ingestion)

ผู้ใช้ลากวางไฟล์ CSV/Excel รายงานของงวดเดือนและเครื่องพิมพ์ยี่ห้อใดๆ เข้าสู่ระบบ

2

AI Schema Normalization & Validation

AI Engine อ่านโครงสร้างหัวคอลัมน์ ยืนยันความถูกต้อง และเปลี่ยนรูปแบบข้อมูลให้พร้อมเก็บลง DB โครงสร้างกลาง

3

PDPA Masking Engine

สกัดและ Mask รหัสพนักงานรวมถึงชื่อพนักงานด้วยอัลกอริทึม (First/Last Char) สำหรับผู้ใช้บทบาทปกติ

4

Database Ingestion & Cache Update

บันทึกประวัติลง PostgreSQL และอัปเดตตารางสรุปรายปี/รายเดือน (MonthlySummaries) อัตโนมัติ

5

YoY Analysis & Chart Rendering

แดชบอร์ดฝั่ง React ดึงข้อมูลจาก API มาแสดงกราฟแนวโน้มข้ามปี และตารางเปรียบเทียบสถิติ YoY

6

Security Logs & Export

บันทึก Log ทุกๆ กิจกรรมการอัปโหลดหรือนำออกรายงานสรุปทางการเงิน (Excel) ของ Admin

Architecture Notes:

ระบบทำงานแบบ 3-tier architecture (React, Node.js/Express, PostgreSQL) โดยเชื่อมต่อกับฐานข้อมูล PostgreSQL บนระบบ Neon Cloud Database เพื่อความมั่นคงสูง และเพื่อเพิ่มประสิทธิภาพสูงสุดในการวิเคราะห์เปรียบเทียบสถิติรายปี (YoY) ระบบมีการออกแบบตารางแคชสรุปข้อมูลประจำเดือน MonthlySummaries เพื่อช่วยลดปริมาณการคิวรีลงตารางหลัก UsageDetails ที่มีข้อมูลดิบปริมาณมหาศาล ป้องกันคิวรีค้างหรือฐานข้อมูลทำงานหนักเกินไป
