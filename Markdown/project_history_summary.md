# รายงานสรุปคำสั่ง คำตอบ และปัญหาที่เกิดขึ้นในระบบ Copier Report Portal

เอกสารนี้รวบรวมประวัติการสั่งการแก้ไข ข้อตกลง และปัญหาที่เกิดขึ้นตั้งแต่เริ่มต้นโครงการจนถึงการปรับปรุงระบบครั้งล่าสุด เพื่อเป็นบันทึกประวัติการดำเนินงาน (History Logs) ของระบบ **Copier Report Portal**

---

## 1. ลำดับเหตุการณ์คำสั่งและคำตอบ (Instruction & Solution History)

### 📌 คำสั่งที่ 1: การสำรองข้อมูลฐานข้อมูล (Database Backup)
* **ความต้องการ:** ต้องการสำรองฐานข้อมูลของระบบเครื่องถ่ายเอกสารและเครื่องพิมพ์ทั้งหมดไว้เพื่อความปลอดภัย
* **แนวทางแก้ไข (คำตอบ):**
  * พัฒนาไฟล์สคริปต์ [backup_database.bat](file:///d:/PythonScript2/backup_database.bat) ที่ Root ของโปรเจกต์
  * รันคำสั่งผ่านระบบ `sqlcmd` ของ Microsoft SQL Server 2019 โดยสำรองฐานข้อมูล `CopierReport` ออกมาเป็นไฟล์แบ็กอัปที่ **`D:\CopierReport.bak`** สำเร็จ

### 📌 คำสั่งที่ 2: การตั้งค่าระบบเชื่อมต่อและจัดการเซิร์ฟเวอร์ (Startup & DB Configuration)
* **ความต้องการ:** ต้องการให้ระบบสามารถรันขึ้นมาพร้อมกันได้ง่าย และแก้ไขระบบหลังบ้าน (Backend) ที่ไม่สามารถสตาร์ททำงานได้
* **แนวทางแก้ไข (คำตอบ):**
  * **Orchestration:** จัดทำไฟล์ `package.json` ที่ Root ของโปรเจกต์ ทำให้สามารถติดตั้ง dependencies ได้พร้อมกันด้วยคำสั่ง `npm run install:all` และรัน backend + frontend ร่วมกันใน terminal เดียวผ่านคำสั่ง `npm run dev`
  * **DB Authentication:** ตรวจพบว่า SQL Server ปฏิเสธบัญชีผู้ใช้ `CopierReport` จึงได้สร้างสคริปต์ [setup_login.sql](file:///d:/PythonScript2/backend/setup_login.sql) เพื่อให้ผู้ใช้ไปรันผ่าน SSMS ในการสร้าง User `CopierReport` (รหัสผ่าน `report123456`) พร้อมกำหนดสิทธิ์เป็น `db_owner` ของฐานข้อมูล `CopierReport`

### 📌 คำสั่งที่ 3: ตรวจสอบความปลอดภัยตามกฎหมาย PDPA (SC-3 Compliance)
* **ความต้องการ:** ตรวจสอบและแก้ไขระบบให้เป็นไปตามนโยบายความเป็นส่วนตัวและความปลอดภัยข้อมูลส่วนบุคคล `[SC-3] Data Masking`
* **แนวทางแก้ไข (คำตอบ):**
  * ตรวจพบไฟล์รายงาน [user_usage_report.md](file:///d:/PythonScript2/Markdown/user_usage_report.md) และสคริปต์ [generate_user_report.py](file:///d:/PythonScript2/scripts/generate_user_report.py) มีการแสดงผลชื่อและรหัสพนักงานจริงแบบไม่ได้ปิดบัง (Unmasked)
  * แก้ไขข้อมูลและเขียนสคริปต์การแปลงข้อมูล (Masking Logic) เพื่อปกปิดข้อมูลให้เหลือเพียงรูปอักขระพิเศษ เช่น `1427` -> `1**7` และ `kanapot` -> `k*****t` เมื่อไม่ได้เข้าสู่ระบบด้วยสิทธิ์ผู้ดูแลระบบ

### 📌 คำสั่งที่ 4: แสดงรุ่นเครื่องพิมพ์และยอดรวมเงินสำหรับแต่ละรอบเดือน (Printer & Total Cost Table Update)
* **ความต้องการ:** ต้องการให้หน้าแดชบอร์ดระบุเครื่องพิมพ์และยอดรวมเงินของไฟล์รายงานแต่ละตัวให้ชัดเจนตามเดือนต่างๆ
* **แนวทางแก้ไข (คำตอบ):**
  * ปรับปรุงหน้าจอสรุปแดชบอร์ด [App.js](file:///d:/PythonScript2/frontend/src/App.js) ในส่วนตาราง *"รายงานประจำเดือนที่นำเข้าระบบล่าสุด"*
  * เพิ่มคอลัมน์แสดง **รุ่นเครื่องพิมพ์และชื่อไฟล์** (ดึงข้อมูลมาจาก `printer_name` และ `filename`) และแสดงคอลัมน์ **ยอดรวมเงิน** (Total Cost) ของข้อมูลแต่ละงวด เพื่อป้องกันความสับสนกรณีอัปโหลดหลายไฟล์ในเดือนเดียวกัน

### 📌 คำสั่งที่ 5: ปิดช่องโหว่ความปลอดภัยระบบยืนยันตัวตน (Authentication Hardening)
* **ความต้องการ:** ตรวจสอบและแก้ไขช่องโหว่ที่ยอมให้เข้าถึง API ได้โดยไม่ผ่านการเซ็นชื่อความปลอดภัยที่ถูกต้อง (JWT Validation) เพื่อให้ตรงกับเกณฑ์ checklist
* **แนวทางแก้ไข (คำตอบ):**
  * แก้ไขไฟล์ [auth.js](file:///d:/PythonScript2/backend/middleware/auth.js) เพื่อยกเลิกตรรกะ bypass การตรวจสอบโทเค็นแบบเก่าทั้งหมด (เช่น `admin-token`, `user-token`, `role:username`) โดยบังคับใช้การตรวจสอบลายเซ็นดิจิทัล JWT เสมอ

### 📌 คำสั่งที่ 6: สร้างระบบทดสอบการทำงานของ API อัตโนมัติ (Automated API Testing Setup)
* **ความต้องการ:** จัดทำชุดทดสอบการทำงานของ API ที่มีขอบเขตครอบคลุมเงื่อนไขปกติ ผิดพลาด และ Edge cases ตามที่ระบุใน checklist
* **แนวทางแก้ไข (คำตอบ):**
  * พัฒนาสคริปต์ [test_api.js](file:///d:/PythonScript2/backend/test_api.js) แบบไม่จำเป็นต้องติดตั้ง dependencies ภายนอก (Zero-dependency) เพื่อรันการทดสอบและแสดงผลรายงานผลผ่าน Node.js โดยตรง

## 2. ปัญหาที่เกิดขึ้นและการแก้ไข (Encountered Issues & Resolutions)

### 🚨 ปัญหาที่ 1: Backend Server Crash (การเชื่อมต่อฐานข้อมูลล้มเหลว)
* **สาเหตุ:** การตั้งค่าสิทธิ์ล็อกอินของ SQL Server Authentication ในเครื่องผู้ใช้ ไม่ตรงกับค่าคอนฟิกในไฟล์ `.env` ของ Backend
* **การแก้ไข:** สร้างและรันไฟล์สคริปต์ [setup_login.sql](file:///d:/PythonScript2/backend/setup_login.sql) เพื่อปรับปรุงบทบาทสิทธิ์ (Role) และสร้าง User ใน Microsoft SQL Server ให้สามารถเข้าถึงฐานข้อมูลได้อย่างสมบูรณ์

### 🚨 ปัญหาที่ 2: ข้อมูลส่วนบุคคลไม่ได้รับความปลอดภัย (PDPA Security Risk)
* **สาเหตุ:** สคริปต์สรุปรายงานและตารางรายงานสรุปเดิมใช้ข้อมูลพนักงานตรงๆ (เช่น ชื่อ, รหัสพนักงาน) ซึ่งขัดต่อนโยบายความปลอดภัยและกฎหมาย PDPA
* **การแก้ไข:** อัปเดตตรรกะใน backend และสคริปต์ Python ในการ Mask ข้อมูลผ่าน Regular Expressions เพื่อซ่อนตัวอักษรและตัวเลขตรงกลางก่อนจัดส่งหรือแสดงผล

### 🚨 ปัญหาที่ 3: ไม่สามารถระบุเครื่องพิมพ์และชื่อไฟล์ที่นำเข้าได้บนแดชบอร์ด
* **สาเหตุ:** ตารางประวัติการนำเข้าไฟล์ล่าสุดในแดชบอร์ดแสดงเพียงรอบงวดเดือน/ปี (เช่น "มิถุนายน 2569") ซ้ำกันหลายแถวตามจำนวนไฟล์ที่นำเข้า ทำให้ผู้ใช้ไม่สามารถระบุได้ว่าแถวใดเป็นของเครื่องพิมพ์หรือไฟล์ตัวใด
* **การแก้ไข:** ปรับปรุงโครงสร้างตารางใหม่โดยดึงข้อมูล `printer_name` ที่คัดแยกมา และ `filename` มาแสดงใต้คอลัมน์ชื่อรุ่นเครื่องพิมพ์อย่างชัดเจน

### 🚨 ปัญหาที่ 4: ตัวเลขรวมยอดเงินหายไปจากตารางหน้าเว็บ (Invisible Cost Value)
* **สาเหตุ:** มีการใช้คลาสไล่เฉดสี `.text-gradient-green` และ `.text-gradient` ซึ่งมีคำสั่ง `-webkit-background-clip: text;` และ `-webkit-text-fill-color: transparent;` โดยตรงบนอิลิเมนต์ `<td>` ของตาราง ซึ่งเบราว์เซอร์ไม่รองรับกับอิลิเมนต์ประเภท Table cells ส่งผลให้ตัวเลขยอดเงินแสดงผลโปร่งใสและกลืนไปกับพื้นหลังสีขาว
* **การแก้ไข:** 
  1. แก้ไขสไตล์ชีต [index.css](file:///d:/PythonScript2/frontend/src/index.css) เพื่อเพิ่ม `display: inline-block` ให้กับคลาสไล่เฉดสี
  2. แก้ไขไฟล์ [App.js](file:///d:/PythonScript2/frontend/src/App.js) เพื่อนำคลาสไล่เฉดสีไปใช้กับแท็ก `<span>` ภายในเซลล์ตารางแทน ส่งผลให้ตัวเลขแสดงผลการไล่เฉดสีเขียว-แดงได้อย่างสวยงามและมองเห็นได้ 100%

### 🚨 ปัญหาที่ 5: ช่องโหว่การข้ามผ่านการตรวจสอบตัวตน (Auth Bypass Backdoor Risk)
* **สาเหตุ:** มีโค้ด fallback ตรวจสอบโทเค็นหลงเหลืออยู่ใน middleware ที่ยอมรับข้อความดิบ เช่น `admin-token` หรือ `admin:username` ส่งผลให้ใครก็ตามสามารถเข้าถึง API สิทธิ์ผู้ดูแลระบบได้โดยไม่ต้องกรอกรหัสผ่านจริง
* **การแก้ไข:** ลบตรรกะดังกล่าวออกจาก [auth.js](file:///d:/PythonScript2/backend/middleware/auth.js) และบังคับการตรวจสอบความถูกต้องลายเซ็น JWT เพียงอย่างเดียว

### 🚨 ปัญหาที่ 6: ขาดชุดเครื่องมือทดสอบความมั่นคงของระบบ (Lack of Automated Tests)
* **สาเหตุ:** โครงการเดิมไม่มีระบบทดสอบการเรียกใช้งาน API ทำให้ตรวจสอบความผิดปกติและช่องโหว่ความปลอดภัยก่อนนำระบบจริงขึ้นใช้งานได้ยาก
* **การแก้ไข:** สร้าง [test_api.js](file:///d:/PythonScript2/backend/test_api.js) และเพิ่มคำสั่งรัน `"test": "node backend/test_api.js"` ใน `package.json` ของ Root เพื่ออำนวยความสะดวกในการสั่งรันตรวจสอบ API
